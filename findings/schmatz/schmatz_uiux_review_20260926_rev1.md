## 3. 良かった点（OK判定）

| 項目 | 判定の根拠 |
|---|---|
| SCH-01 状態の区別 | 「本人の連絡」と「実績の状態」が別の列・別のバッジで表示され、「確定済みの出席率ではありません」などの注記もある |
| SCH-02 幅320pxで完結 | 全画面で横はみ出しなし。社員の入力・確認画面は320pxでも主ボタンが下部ナビに隠れない |
| SCH-04 誤操作防止 | 例外連絡はメニュー経由で、「選択だけでは送信されません」と明示されている |
| SCH-05 確定済みと確認用 | 出力の最終確認に「実績の範囲：確定済みのみ」「未確定データ：0件／出力から除外」が明示されている |
| ERR-01 破壊的操作 | 取消・確定・出力はすべて確認画面を経由する。一括確定は対象者と件数を表示し、確認のチェックを必須にしている |
| FRM-01／FRM-02 入力 | 常時表示のラベル、「必須」表示、文字数上限の補足がある |
| A11Y-04 名前・役割 | axe で名前・役割関連の違反なし |

## 4. 今回評価していない項目

- **人による操作確認が必要な項目**：A11Y-03（キーボード操作）、A11Y-05（200%拡大）、FRM-04（離脱時の入力保持）、SCH-06（出力後の表示。README とテスト結果では対応済み）
- **実装段階で評価する項目**：FBK-01（処理中表示）、ERR-03（システムエラー）、AUTH-01（権限）、NTF-01（通知）
- **実機での確認**：iOS Safari と Android Chrome の実機では未確認です。今回の日付入力欄は検証環境のロケールで英語表記（04/08/2026）になっていますが、日本語環境では日本語表記になる想定のため、指摘に含めていません。

## 5. 推奨する対応順

1. **SCH-01・02・03（文言の一括修正）**：用語集どおりに置換するだけで済みます。Claude Code に置換表を渡して実施するのが効率的です。
2. **SCH-04（色トークンの修正）**：補足テキストのトークンを `#5a6c64` 程度に変えれば全画面で解消する見込みです。
3. **SCH-05・06（文字サイズとタップ領域の下限）**：共通CSSで下限値を指定して対応します。
4. **SCH-07〜10（個別画面の改善）**
5. **SCH-11（モック用表示）**：本番化の時点で除去します。
