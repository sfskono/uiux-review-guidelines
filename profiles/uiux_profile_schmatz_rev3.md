# L3プロファイル：schmatz（研修出席管理）rev3

## 1. サービス概要

- 新入社員研修の出席連絡・申請管理・出席実績の確定・出力を、社員・講師・人事担当・コースマネージャの4つの立場で扱うWebサービス。
- 設計の軸：「連絡はすぐに。状況は明確に。確認は確実に。」
- 静的HTMLモックに加え、React / Vite / MSWの操作モックをレビューする。今回の参照は `sfskono/schmatz` の `fbaabefb4cfffe74028d82cf2d07a5fc8efff875`。本番の認証・サーバー側認可・業務API・自動通知・外部連携の合格を意味しない。
- レスポンシブ対応は初期リリースの受入条件（Must）。社員はモバイルファースト、人事・コースマネージャもスマホで業務を完結できること。

## 3. 初回レビューの進め方（案）

現段階はモックなので、**DS フェーズ（デザイン）を中心に評価**します。本番の挙動に依存する項目（性能・実際の保存・端末間の同期など）は、IMP フェーズで改めて評価します。

1. 役割ごとの主要タスク（T1〜T6）に沿って、幅390px（スマホ）と1440px（PC）で画面を操作し、スクリーンショットを取得する。
2. `method: llm` の項目は、スクリーンショットとこのプロファイルを渡して LLM が一次判定し、人が最終判定する。
3. SCH-03 はリポジトリの Playwright テストに、タップ領域の計測を追加して自動判定する。
4. 指摘は `findings/schmatz/` 配下に、ガイドライン §6 の書式で記録する。

## 4. モバイルのヘッダー・当日研修領域の再レビュー（改訂案）

この版はガイドライン見直しの案であり、UI改修済み・人による受入済みとは扱わない。SCH-01〜08はrev2から保持し、SCH-09〜11を追加する。共通L2はrev2のままで、新しい共通Mustには昇格しない。

[判断補足](../guideline/mobile_task_layout_review_rev1.md)と[今回の指摘記録](../findings/schmatz/20261003_mobile_layout_review.md)を参照する。

- 対象は社員のスマホ画面群。同じ役割・ブレークポイントでホーム、申請一覧、ヘルプの導線を比較する。人事・講師・コースマネージャの会社識別を社員画面と同じ理由で削除しない。
- 「ヘッダー不要」を共通規則にしない。ロゴ専用行の統合と機能の削除は別で、アカウント名・会社・ログアウト・戻る手段が必要なら常設または一貫したアクセス手段を残す。
- 「今日の研修」の見出しと対象日は保持し、独立した広い帯ではなく研修情報の先頭へ統合する案を比較する。h1の意味・読み上げ・画面遷移後フォーカスを保持する。対象研修0件でも見出しを残し、複数研修ではページh1をカードごとに複製しない。
- 見出し・名称・時間会場は判断材料。未連絡／受付済み／講師の実績確定、送信ボタン、例外連絡の入口は主要コンテンツ。カードが大きいことだけで不合格にしない。
- 原則的な改善順序は、独立行や重複表示の整理→グルーピング→余白トークン→役割に応じた文字サイズ。16pxの名称や48pxの操作領域をさらに削って上部構造の問題を隠さない。
- 320×568、375×667、390×844、430×932 CSS pxで未連絡・受付後を比較し、上部導入部分の高さ、業務情報の開始位置、操作ボタン・固定ナビの矩形と重なりを記録する。これはプロジェクトの検証条件で、WCAGの画面占有率規定ではない。
- 空状態、複数研修、長い名称、通信／保存エラー、デモ設定展開、200%文字・実ズーム、ソフトキーボードとsafe areaでは必要な縦スクロールを許容する。重要情報・文字・機能を切らない。
- 数値検査と、利用者が日付・対象・状態・次の操作を説明できるかの人による判定を別に記録する。指摘は未実装ならopen、再レビューまで未検証とする。
